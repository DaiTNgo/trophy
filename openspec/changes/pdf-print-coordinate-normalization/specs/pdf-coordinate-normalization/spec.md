## ADDED Requirements

### Requirement: Extract 1x dimensions for Customization Backgrounds
When a PDF is uploaded as a customization background, the system MUST extract and store the native PDF dimensions (scale: 1.0) into the database's `widthPx` and `heightPx` fields, even though a higher-resolution 2x image is generated for preview purposes.

#### Scenario: PDF is uploaded as a background
- **WHEN** the user uploads a PDF for a product customization background
- **THEN** the system generates a 2x WebP image for preview
- **THEN** the system stores the 1x dimensions (in native PDF points) in the `widthPx` and `heightPx` fields

### Requirement: Maintain 1x coordinate mapping in the Editor Canvas
The UI Editor Canvas MUST restrict its rendering container to the 1x dimensions saved in the database, shrinking the high-resolution 2x preview image to fit perfectly inside it, ensuring all user interaction coordinates are naturally mapped at 1x scale.

#### Scenario: User draws blocks on the customization editor
- **WHEN** the editor loads a customization background derived from a PDF
- **THEN** the canvas renders at the 1x dimensions extracted from the database
- **THEN** user interactions result in coordinates that map directly to the native 1x PDF size

### Requirement: Export vector PDFs at native 1x scale
The system MUST generate vector PDFs for print production at exactly the native 1x size (as stored in the database), without manually scaling down coordinates during export.

#### Scenario: Generating a print-ready vector PDF
- **WHEN** an operator exports the vector PDF for a customized order
- **THEN** the generated PDF page matches the native 1x dimensions stored in the database
- **THEN** all customized elements are accurately positioned based on the 1x coordinates generated by the editor
